# AutoFlow 宏与 Rhai 脚本详细使用说明

本文适用于当前 Windows 桌面版 AutoFlow，介绍图形宏、宏录制、兼容 Rhai 源码、高级 Rhai 脚本，以及窗口、像素和图像识别功能。

## 1. 开始之前

宏会真实发送键盘和鼠标输入。第一次使用时，建议先打开记事本或其他无风险窗口测试。

- `F12` 是紧急停止键，可随时终止正在播放的宏或脚本。
- `Ctrl + Shift + F9` 是宏录制的开始/停止快捷键，不能作为普通宏的触发组合。
- 同一时间只运行一个宏或脚本；正在运行时再次启动其他宏会失败。
- AutoFlow 会在正常结束、停止或报错后释放它按下的键和鼠标按钮。
- 如果目标程序以管理员身份运行，AutoFlow 通常也需要以管理员身份启动，否则 Windows 可能拒绝模拟输入。

浏览器预览版只用于查看和编辑界面，不能监听全局键盘，也不能可靠执行桌面录制、窗口捕获或找图。完整功能请使用 Windows 桌面版。

## 2. 图形宏快速入门

### 2.1 从参考宏开始

1. 打开左侧导航中的“宏”。
2. 在“我的宏”标题下找到“参考宏”。
3. 选择一个模板并点击“添加参考宏”。
4. AutoFlow 会复制一份模板到“我的宏”，原模板不会被修改。
5. 修改名称、触发组合、步骤参数后，先点击“测试播放”。
6. 确认结果正确后再点击“启用宏”。

当前参考代码包括普通键鼠流程、随机等待、窗口内找图和像素等待。其中的坐标、窗口标题、颜色和图像文件名都是示例值，必须按实际目标修改。

### 2.2 新建空白宏

1. 点击页面右上角或宏列表底部的“新建宏”。
2. 填写宏名称。
3. 点击“触发组合”输入框，再按下需要的组合键，例如 `Ctrl + F8`。
4. 选择运行模式和整体速度。
5. 使用录制功能，或手动添加步骤。
6. 使用“测试播放”验证。
7. 点击“启用宏”，此后在其他窗口按触发组合即可运行。

页面会自动保存修改。底部显示“已自动保存”后即可离开当前宏。

## 3. 宏设置

### 3.1 触发组合

点击触发输入框后直接按组合键。常用按键名称包括：

- 修饰键：`Ctrl`、`Alt`、`Shift`、`Win`
- 字母和数字：`A`–`Z`、`0`–`9`
- 功能键：`F1`–`F24`
- 其他键：`Esc`、`Enter`、`Space`、`Tab`、`Backspace`、`CapsLock`
- 方向键：`Left`、`Right`、`Up`、`Down`

不要使用 `F12` 作为普通触发键。`Ctrl + Shift + F9` 保留给录制功能。

### 3.2 运行模式

| 模式     | 行为                             | 适用场景               |
| -------- | -------------------------------- | ---------------------- |
| 单次     | 每次触发只执行一轮               | 打开菜单、填写一次表单 |
| 固定次数 | 触发后按设定次数重复             | 重复点击或批量录入     |
| 按住循环 | 按住触发组合时循环，松开即停止   | 临时连续操作           |
| 开关循环 | 第一次按下开始，再按相同组合停止 | 长时间循环任务         |

无论使用哪种模式，都可以按 `F12` 强制停止。

### 3.3 整体速度

- `1.0×`：按原始等待时间执行。
- 大于 `1.0×`：更快，例如 `2.0×` 会缩短等待。
- 小于 `1.0×`：更慢，例如 `0.5×` 会延长等待。
- 当前界面允许的范围为 `0.05×`–`10×`。

速度主要影响等待时间。鼠标坐标、按键内容和图像匹配阈值不会随速度变化。

## 4. 录制宏

### 4.1 录制步骤

1. 新建或选中一个图形宏。
2. 选择是否录入“鼠标移动”和“鼠标点击与滚轮”。
3. 点击“开始录制”。
4. 切换到目标程序。AutoFlow 第一次失去焦点后开始捕获，首次用于聚焦目标窗口的操作不会被录入。
5. 完成操作后按 `Ctrl + Shift + F9`，或回到 AutoFlow 点击“停止录制”。
6. 录制结果会追加到当前宏已有步骤之后。

以下内容不会被录入：

- `Ctrl + Shift + F9` 录制快捷键本身；
- AutoFlow 窗口内的操作；
- 第一次将焦点切换到目标窗口的动作。

### 4.2 录制后的整理建议

- 删除无意义的短等待和多余鼠标移动。
- 在窗口切换、页面加载和弹窗出现前保留足够等待时间。
- 对不稳定的加载时间使用随机等待，或改用 `wait_window`、`wait_pixel`、`wait_image`。
- 检查每个“按下”步骤是否有对应的“释放”步骤。
- 使用拖动手柄、上移和下移按钮调整顺序；可复制或删除单个步骤。

## 5. 图形步骤说明

### 5.1 等待

只填写最小时间时为固定等待；同时填写最大时间时，每次会在区间内随机等待。

示例：最小值 `300`、最大值 `800`，表示每次等待 300–800 毫秒。

### 5.2 按键

“按下”和“释放”是两个独立步骤。组合键应按以下顺序排列：

1. 按下 `Ctrl`
2. 按下 `C`
3. 释放 `C`
4. 释放 `Ctrl`

普通单键也建议成对添加。源码中可以使用 `press("Enter")` 自动完成按下和释放。

### 5.3 鼠标点击

鼠标按钮支持：

- `left`：左键
- `right`：右键
- `middle`：中键
- `x1`：侧键 1
- `x2`：侧键 2

图形界面把按下和释放保存为独立步骤。一次完整点击通常包含同一坐标的“按下”和“释放”。

### 5.4 鼠标移动

将鼠标指针移动到物理屏幕坐标 `(x, y)`。扩展显示器位于主屏左侧或上方时，坐标可能为负数。

更换显示器排列、缩放比例或窗口位置后，应重新检查坐标宏。

### 5.5 滚轮

- `deltaX`：水平滚动量。
- `deltaY`：垂直滚动量。
- 常见的一格向下滚动为 `(0, -120)`，向上为 `(0, 120)`。

具体滚动方向和距离可能受目标程序设置影响。

### 5.6 文本

文本步骤适合输入中文、多行文本和符号。快捷键、导航键或功能键应使用按键步骤，不要把它们写进文本步骤。

## 6. 源码模式：兼容宏与高级 Rhai

选中宏后点击“源码”即可编辑 Rhai 源码。

### 6.1 兼容宏源码

兼容宏源码可以安全地转换回图形步骤。规则是：

- 每行只有一个 AutoFlow API 调用；
- 每行以分号 `;` 结束；
- 不使用变量、条件、循环或自定义函数；
- 字符串使用双引号；
- 参数只使用字符串或整数。

示例：

```rhai
key_down("Ctrl");
press("C");
key_up("Ctrl");
wait_random_ms(300, 800);
move_to(820, 430);
click("left", 820, 430);
type_text("AutoFlow 示例文本");
```

点击“检查”可验证语法，点击“格式化”可整理兼容源码。点击“应用并切回图形界面”后，源码会转换为图形步骤。

`press(key)` 会转换成成对的按下/释放步骤；`click(button, x, y)` 会转换成成对的鼠标按下/释放步骤。

### 6.2 高级 Rhai 脚本

源码包含 `let`、`if/else`、`for`、`while` 或 `fn` 时，会被识别为高级脚本。高级脚本会保留原始源码，不能直接显示成图形步骤。

示例：等待窗口后执行操作：

```rhai
if wait_window("记事本", 10000, 200) {
    type_text("窗口已经出现");
    press("Enter");
}
```

示例：有限次数循环：

```rhai
for index in 0..5 {
    if is_cancelled() {
        break;
    }

    click("left", 820, 430);
    wait_random_ms(500, 900);
}
```

示例：定义函数：

```rhai
fn submit_once(x, y) {
    click("left", x, y);
    wait_ms(500);
    press("Enter");
}

submit_once(820, 430);
```

如果要让高级脚本重新变成图形宏，请删除变量、条件、循环和函数，只保留兼容的顶层 API 调用，然后应用源码。

## 7. AutoFlow API v1

### 7.1 等待与取消

| API                        | 说明                                            |
| -------------------------- | ----------------------------------------------- |
| `wait_ms(ms)`              | 固定等待，`ms` 必须为非负整数                   |
| `wait_random_ms(min, max)` | 在闭区间内随机等待，两个值均非负且 `max >= min` |
| `is_cancelled()`           | 返回是否收到停止请求，适合在循环中主动退出      |

整体速度会作用于 `wait_ms` 和 `wait_random_ms`。

### 7.2 键盘、鼠标与文本

| API                        | 说明                                   |
| -------------------------- | -------------------------------------- |
| `key_down(key)`            | 按下指定键                             |
| `key_up(key)`              | 释放指定键                             |
| `press(key)`               | 按下并立即释放指定键                   |
| `move_to(x, y)`            | 移动到物理屏幕坐标                     |
| `mouse_down(button, x, y)` | 在坐标处按下鼠标按钮                   |
| `mouse_up(button, x, y)`   | 在坐标处释放鼠标按钮                   |
| `click(button, x, y)`      | 在坐标处完成一次点击                   |
| `click(x, y)`              | 高级脚本中可用，等同于指定坐标左键点击 |
| `scroll(delta_x, delta_y)` | 发送水平和垂直滚轮量                   |
| `type_text(text)`          | 输入非空文本                           |

坐标和滚动量必须在 32 位有符号整数范围内。

### 7.3 窗口 API

| API                                       | 返回值 | 说明                                     |
| ----------------------------------------- | ------ | ---------------------------------------- |
| `active_window_title()`                   | 字符串 | 获取当前前台窗口标题                     |
| `window_exists(title)`                    | 布尔值 | 判断标题中是否包含查询文本，不区分大小写 |
| `window_rect(title)`                      | Map    | 获取匹配窗口的物理屏幕矩形               |
| `wait_window(title, timeout_ms, poll_ms)` | 布尔值 | 在超时前轮询等待窗口出现                 |

`window_rect` 返回以下字段：

```rhai
#{
    found: true,
    x: 100,
    y: 80,
    width: 1200,
    height: 800
}
```

推荐先判断 `found`：

```rhai
let window = window_rect("记事本");
if window.found {
    click("left", window.x + 100, window.y + 80);
}
```

标题查询使用“包含匹配”。标题过短可能匹配到错误窗口，建议使用足够明确的文本。

### 7.4 像素 API

| API                                                         | 返回值 | 说明                         |
| ----------------------------------------------------------- | ------ | ---------------------------- |
| `pixel_matches(x, y, r, g, b, tolerance)`                   | 布尔值 | 检查单个坐标是否接近目标 RGB |
| `wait_pixel(x, y, r, g, b, tolerance, timeout_ms, poll_ms)` | 布尔值 | 轮询等待目标颜色出现         |

`r`、`g`、`b` 和 `tolerance` 的范围都是 `0`–`255`。容差越大，允许的颜色偏差越大。

示例：最多等待 5 秒，每 200 毫秒检查一次：

```rhai
if wait_pixel(100, 200, 32, 64, 128, 8, 5000, 200) {
    press("Enter");
}
```

### 7.5 图像查找 API

| API                                                                          | 返回值 | 说明                                 |
| ---------------------------------------------------------------------------- | ------ | ------------------------------------ |
| `find_image(file_name, x, y, width, height, threshold)`                      | Map    | 按完整文件名在指定区域查找一次       |
| `wait_image(file_name, x, y, width, height, threshold, timeout_ms, poll_ms)` | Map    | 按完整文件名轮询查找，直到找到或超时 |

返回 Map 包含：

```rhai
#{
    found: true,
    x: 820,
    y: 430,
    width: 120,
    height: 36,
    center_x: 880,
    center_y: 448,
    score: 0.96
}
```

未找到时 `found` 为 `false`，其余坐标和尺寸为 `0`，`score` 为 `0.0`。

完整示例：

```rhai
let window = window_rect("记事本");

if window.found {
    let result = wait_image(
        "confirm_button.png",
        window.x,
        window.y,
        window.width,
        window.height,
        0.90,
        10000,
        200
    );

    if result.found {
        click("left", result.center_x, result.center_y);
    }
}
```

## 8. 图像资源管理

图像查找不能直接读取任意文件路径。图片统一保存在 AutoFlow 的 `data/images` 文件夹：

1. 打开宏的“源码”页签。
2. 在“图像资源”区域点击“导入 PNG/JPEG”，或者打开图像文件夹后直接复制图片进去。
3. 选择或放入一张 PNG、JPG 或 JPEG 图片；直接添加文件后点击“刷新”。
4. 点击资源卡片中的“复制文件名”。
5. 把复制的完整文件名填入 `find_image` 或 `wait_image` 的第一个参数。必须包含 `.png`、`.jpg` 或 `.jpeg` 后缀。

素材建议：

- 只截取稳定且有辨识度的按钮或图标，避免大面积空白。
- 素材应与实际显示缩放、主题、字体和窗口状态一致。
- 优先在目标窗口范围内找图，不要直接搜索整个桌面。
- `threshold` 范围为 `0.0`–`1.0`；可从 `0.90` 开始，误匹配时提高，找不到时适当降低。
- 删除素材会使引用该文件名的脚本失效。

## 9. 视觉参数与多显示器

- 所有窗口、像素和找图坐标均为 Windows 物理屏幕坐标。
- 副显示器在主显示器左侧或上方时，`x` 或 `y` 可以为负数。
- 捕获区域的宽度和高度必须大于 `0`。
- 单次区域最大边界为 `7680 × 4320`，总像素数不能超过 `8,388,608`。
- `timeout_ms` 范围为 `0`–`120000` 毫秒。
- `poll_ms` 范围为 `50`–`5000` 毫秒，通常建议 `150`–`250` 毫秒。

接入、断开或重新排列显示器后，固定坐标可能改变。应先重新测试坐标宏和视觉脚本，再启用全局触发。

## 10. 完整实用示例

### 10.1 等待窗口，找到按钮并点击

```rhai
let title = "目标程序";

if wait_window(title, 15000, 200) {
    let window = window_rect(title);
    let button = wait_image(
        "submit_button.png",
        window.x,
        window.y,
        window.width,
        window.height,
        0.92,
        10000,
        200
    );

    if button.found {
        click("left", button.center_x, button.center_y);
    }
}
```

### 10.2 等待状态颜色后输入文本

```rhai
if wait_pixel(640, 360, 24, 180, 90, 12, 30000, 200) {
    click("left", 720, 520);
    type_text("任务已完成");
    press("Enter");
}
```

### 10.3 可随时停止的重复任务

```rhai
for round in 0..100 {
    if is_cancelled() {
        break;
    }

    click("left", 820, 430);
    wait_random_ms(800, 1200);
}
```

### 7.6 图像匹配高级选项

`find_image` 和 `wait_image` 继续支持原有参数签名，也支持最后追加一个
`options` Map：`mode` 可取 `"auto"`、`"exact"` 或 `"fast"`，
`prefer_last` 控制是否优先复用上一命中区域，`max_candidates` 范围为
1–32，`scale_min`/`scale_max` 是模板倍率（`1.25` 表示 125%，不是
百分数），范围为 `0.5`–`2.0`；`scale_step` 可选且必须为正数。例如：

```rhai
let result = find_image(
    "confirm_button.png", 0, 0, 1920, 1080, 0.90,
    #{
        mode: "auto",
        scale_min: 0.65,
        scale_max: 1.60,
        prefer_last: true,
        max_candidates: 8
    }
);
```

未指定尺度时，`auto` 和 `fast` 默认覆盖常见 Windows DPI 倍率：
`0.67`、`0.80`、`0.83`、`1.00`、`1.20`、`1.25`、`1.50`（并受自定义范围
限制）。`auto` 使用上一命中位置和尺度、多尺度低分辨率粗匹配、跨位置/尺度
候选筛选及对应缩放模板的原图局部复核；结果不确定时才执行受控的全区域 NCC
fallback。`fast` 保留多尺度粗匹配和局部复核，但不执行全区域 fallback。
`exact` 固定使用 1.0 倍全分辨率 NCC，明确不负责跨尺度匹配。

返回 Map 在原有 `found`、坐标、尺寸和 `score` 外还包含
`total_ms`、`capture_ms`、`prepare_ms`、`coarse_ms`、`refine_ms`、
`fallback_ms`、`candidate_count`、`previous_hit_used`、`fallback_used`、
`matcher_mode`、`matched_scale`、`scale_candidates`、`scale_search_ms`、
`matched_width` 和 `matched_height`。命中时 `matched_width`/`matched_height`
是实际缩放模板尺寸，未命中时 `matched_scale` 为 Rhai 空值 `()`，尺寸为
`0`。旧脚本不读取这些字段时行为不变；图片仍必须使用 `data/images` 中的
完整文件名，资源扩展名规则不变。

避免没有等待的无限循环。即使引擎有操作数限制，这类循环仍会快速消耗执行预算，也会让目标程序接收过多输入。

## 11. 安全边界

Rhai 脚本只能调用 AutoFlow 注册的 API，不能访问：

- 文件读写；
- 网络请求；
- 启动或控制进程；
- 系统命令；
- 动态模块和任意代码加载。

当前执行限制包括：

- 最多 `100,000` 次 Rhai 操作；
- 最多 `32` 层函数调用；
- 最多 `64` 层表达式或作用域深度；
- 单个字符串最大约 `1 MB`；
- 单个视觉等待最长 `120` 秒。

达到限制、语法错误、视觉捕获失败或按下 `F12` 时，脚本会停止并显示错误。

## 12. 常见问题

### 宏按触发键没有反应

检查以下项目：

1. 全局总开关是否开启；
2. 当前宏是否已启用；
3. 触发组合是否完整且没有与其他规则冲突；
4. 是否正在录制或已有另一个宏正在运行；
5. 目标程序是否以更高权限运行。

### 测试播放后点错位置

- 显示器排列、分辨率、缩放或窗口位置可能已经改变。
- 重新录制坐标，或使用 `window_rect` 计算相对窗口位置。
- 对会移动的按钮，优先使用 `find_image`。

### 找图一直返回 `found = false`

- 确认使用的是包含扩展名的完整文件名，例如 `confirm_button.png`；后缀不能省略。
- 确认素材没有被删除，预览中没有显示“文件不存在”。
- 检查搜索区域是否覆盖目标图像。
- 检查显示缩放、主题、亮暗模式和按钮状态是否与素材一致。
- 尝试把阈值从 `0.95` 调低到 `0.90` 或 `0.85`。

### 像素等待经常超时

- 检查坐标是否仍然正确。
- 适当增加颜色容差，例如从 `5` 调整到 `10` 或 `15`。
- 增加超时时间，但不要超过 `120000` 毫秒。
- 动画区域颜色不稳定时，改用较稳定的图像特征。

### 高级脚本无法切回图形界面

图形编辑器只能表示顶层动作调用。删除 `let`、`if`、循环、函数和表达式，只保留每行一个兼容 API 调用，语法检查通过后再应用源码。

### 如何安全调试

1. 保持宏处于停用状态。
2. 把循环次数改小，等待时间适当加长。
3. 在记事本或测试窗口中使用“测试播放”。
4. 随时准备按 `F12`。
5. 确认无误后再启用全局触发。
