# AutoFlow 运行与输入安全人工验收手册

## 简明执行版

> 当前状态：本轮 Hold“保持普通键、释放修饰键后启动”尚未人工验收；以下步骤是待执行操作，不代表已经通过。

这一部分只回答三件事：做什么、应该看到什么、不符合时怎么办。请从第 1 步开始，严格按顺序执行，不要跳步。

开始前先记住：

- 本手册中的测试脚本出厂状态都是**禁用、没有快捷键**。每次只启用一个，运行结束或中途停止后立即重新禁用，并再次确认快捷键为空。
- 如另行复核普通启动快捷键：`Once`（单次）和 `Repeat`（次数循环）在按住组合键时不能出现任何动作；必须等组合中的所有键都物理松开并短暂稳定后，脚本才可开始。只松开最后一个主键、仍按着 Ctrl/Shift/Alt/Win 时，也不能开始。
- 物理 F12 是例外：按下 F12 的瞬间就应开始停止并撤销输入权限，不等 F12 松开。已运行的 Toggle/连点器再次按停止快捷键时也应立即停止，不等待组合键松开。
- `Hold`（按住循环）的快捷键必须且只能有一个普通“保持键”，可以另加 Ctrl/Shift/Alt/Win。按下完整组合后，继续按住普通键并松开全部修饰键；修饰键稳定释放后脚本才开始。之后再次按下或松开修饰键都不应停止，只有松开普通键才停止。只有一个普通键、没有修饰键时可立即开始。没有普通键、含多个普通键或未知键的 Hold 不能启用。
- 离线页面的“观察状态”为“已知”时，只表示页面从本会话开始连续看到了成对事件；窗口失焦或页面隐藏后会变成“不确定”，重新获得焦点不会自动恢复为“已知”。此时先导出结果并把本轮记为失败或无法确认，不要用页面上“无已跟踪键”证明物理键已经释放。“开始新会话并清空”会保存上一会话快照并清空当前显示，但同样不会声称物理释放。Hold 的保持键 keydown/自动重复会被 AutoFlow 主动拦截，页面可能只看到该键的 keyup 并因此标记“不确定”；这一个明确原因不能证明失败或释放成功，必须同时保存运行时 Hold 诊断，并以输出停止、生命周期结束和清理证据判定。
- 任一步与预期不一致，都要立即停止并保存证据，不进入下一步。不要靠“再试一次”把失败改成通过。
- 事故宏“渡鸦开门”不是测试脚本，验收期间禁止导入、启用、运行或绑定快捷键。
- 需要按物理 F12 的步骤，要分别记录两个时间：
  - **开始停止用了多久**：从按下 F12 到界面显示正在停止，或肉眼看到输入动作停止。
  - **完全停止并清理用了多久**：从按下 F12 到界面进入安全状态，而且离线页面不再显示有按住的键或鼠标按钮。
- 这里的时间要求是本手册的验收标准，不是软件承诺的硬实时保证。

### 第 6 步：文本和单键

- **我要做什么：** 导入 `01-graphical-text-smoke.json` 和 `07-single-key.json`，确认两者仍是禁用且无快捷键。一次只启用一个：在 AutoFlow 点击运行后，利用 3 秒倒计时切回离线页面并点击文本框；运行结束后立即禁用。运行 `01` 后清空文本框，再用同样方式运行 `07`。基本检查通过后，把 `07` 改为 Hold 并绑定 `Ctrl + 7`：按住 Ctrl 和 7，保持 7 不松手，只松开 Ctrl；看到输入后可再按下并松开 Ctrl，最后松开 7 并立即禁用、清空快捷键。另在禁用状态只绑定 `Ctrl`，确认它不能被启用为 Hold；不要手工改 JSON 拼接多个普通键或未知键，这两类拒绝由自动化测试覆盖。
- **预期是什么：** `01` 只输入 `AUTOFLOW_MANUAL_SMOKE`；`07` 的普通运行只输入一个 `a`。Hold 轮在 Ctrl 仍按住时没有 `a`，Ctrl 松开并短暂稳定后才连续输入 `a`；再次按下或松开 Ctrl 不会停止，松开保持键 7 后立即停止。只有单个普通键的 Hold 可以立即开始；只含 `Ctrl` 的 Hold 显示清楚的中文拒绝原因，多个普通键或未知键也不能通过配置校验。脚本输出的 A 按下/松开应成对；保持键 7 的 keydown/自动重复被拦截后，页面可能只记录 keyup 并显示“不确定”，需与 Hold 运行时诊断一起保存，不能据此单独判失败或通过。
- **如果不符合怎么办：** 立即按物理 F12，记录两个停止时间，禁用当前脚本，不进入第 7 步。焦点没有及时切回离线页面也算失败，不要继续。

### 第 7 步：物理 F12 和按键释放

- **如果不符合怎么办：** 立即停止，不进入第 8 步。若 Shift 仍生效或状态不明，不要点击其他业务窗口；保存证据并注销测试账户或重启测试机。

### 2. 验收前备份、恢复与人工边界

#### 2.1 备份

2. 先从 UI 正常退出候选；若 UI 不可用，只针对已记录且核对过的候选 PID/角色执行退出或终止。确认这些 PID 全部退出，不能使用模糊名称或“结束所有 AutoFlow 进程”。

4. 将候选 exe 复制到备份目录，例如 `candidate\autoflow.exe`，并立即记录：

5. 备份 AutoFlow 日志和本手册使用的截图/导出结果。确认备份路径不在待测试的 `data\scripts` 目录内。

#### 2.2 恢复

恢复只针对本轮明确识别的候选和角色。先按物理 F12，记录停止请求时延和清理完成时延；若状态不可信，使用任务管理器核对命令行、PID 和角色后，只结束本轮候选的 GUI、安全服务或 executor PID。不得使用“结束所有 AutoFlow 进程”、模糊名称或全局进程通配符。

#### 2.3 尚未由黑盒人工包覆盖的边界

原生 Windows `SendInput` 的“部分成功”以及释放调用失败，不能由黑盒夹具可信地模拟或证明。它们必须保留为专用 fault-injection build 的未验证边界；本手册的静态 down/up 配对和正常物理 F12 观察不能替代该证据。任何这类注入构建必须有独立候选哈希和独立审批，不能混入本包。

#### 3.2 离线 harness

`tests/manual/runtime-safety-harness.html` 的标题必须完整显示为 `AutoFlow Manual Acceptance Harness`。它与同目录的 `runtime-safety-harness-state.cjs` 构成完全离线的验收页面，不发起网络请求，不自动启动程序，也不合成键鼠事件。页面提供安全指针区域、键盘/鼠标日志、按下状态、ISO 时间戳，以及仅由操作员点击触发的“复制结果”和“导出结果”。键盘物理身份优先使用非空 `event.code + location`；缺少 `code` 时只对 ASCII 字母大小写做保守配对，不把不同 Unicode 键合并。日志和导出保留原始 `key`、`code`、`location`、`repeat` 与四种修饰键标志。

页面另行显示“观察状态”：初始连续观察为“已知”；一旦窗口失焦、页面隐藏或出现无法配对的释放事件，就转为“不确定”，重新聚焦或重新显示不会静默恢复。点击“开始新会话并清空”会先把旧会话状态写入 `previousSessionSnapshot`，再清空当前跟踪集合并把新会话标记为“不确定”；它既不保留无法追溯的旧按下状态，也不宣称对应物理键已经释放。文本框证据单独写入 `textEvidence`，不得用文本内容反推按键按下状态。Hold 的保持键 keydown 与自动重复由生命周期主动抑制，harness 可能只收到保持键 keyup 并转为“不确定”；该轮必须在失焦/隐藏前导出，并结合 `macro_hold_*` 运行时诊断、输出停止和清理证据判断，不能用“不确定”或“无已跟踪键”单独证明成功。

可在仓库根目录显式打开它：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\manual-acceptance.ps1 -Operation OpenHarness
```

这条命令只允许打开仓库内这个固定 HTML；Validate 和 Install 不会启动浏览器或 AutoFlow。人工验收也可以由操作员在资源管理器中双击该本地文件。

#### 3.3 静态 Validate 与安装

从仓库根目录运行（默认操作）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\manual-acceptance.ps1
```

预期每个 JSON 都输出 `VALID`，最后明确说明没有启动应用、没有发送输入。它检查顶层/程序/步骤白名单，唯一 ID/名称，名称中的 `MANUAL_TEST`，禁用和空触发，`once`，无 `behaviorPolicy`，无 F10/F12，无用户绝对路径，Rhai API 白名单，等待/轮询/阈值边界，harness 窗口矩形坐标，down/up 的顺序和数量；包含视觉 API 的夹具还必须是 `window_rect` + `stop_with_message` 的 observer-only 分支，禁止视觉结果后接输入调用。静态配对仍不能证明取消路径的清理，必须完成对应人工等级。

本包的静态夹具界限是：`delay`/`wait_ms`/视觉 timeout 为 `0–120000 ms`，视觉 poll 为 `50–5000 ms`，宏步骤为 `1–512`，文本长度为 `1–16384` 字符；视觉 threshold 为 `0.0–1.0`。这些是本手册夹具的审查边界，不是运行时硬实时 SLA。

安装前必须由操作员在 AutoFlow UI 打开脚本目录，确认该目录的最后两级恰为 `data\scripts`，再显式传入；脚本不会创建任意目录、发现 AppData 或覆盖文件：

```powershell
$scripts = '<由 AutoFlow UI 显示的 data\scripts 完整路径>'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\manual-acceptance.ps1 `
  -Operation Install -Destination $scripts
```

同名文件存在时，安装器先复制到唯一临时备份目录然后拒绝覆盖；由操作员检查并处理冲突后再决定是否重试。安装后必须刷新 UI，确认所有夹具仍是禁用且没有触发键。不要把原始 `.rhai` 文件放入脚本目录。

#### 3.4 视觉目标准备

`tests/manual/assets/manual-vision-target.svg` 是仓库内可审计的参考资源，不是自动导入的成功模板。若运行时只接受栅格图：保持 harness 窗口大小、DPI 和浏览器缩放不变，在 harness 中显示 `VISION TARGET`，用 Windows 截图工具只截取完整目标块，保存为 `manual-vision-target.png`，再通过 AutoFlow 的图像资源 UI 导入并记录资源 ID。任何尺寸、DPI 或缩放改变都要重新截图和导入。不能声称仓库 SVG 或一个未经当前机器准备的 PNG 自动命中。

#### 3.5 固定几何准备门禁（不通过即 BLOCKED）

在任何单击、按住、拖拽或仿生输入前，必须完成以下固定准备：浏览器缩放为 100%，页面没有滚动条或滚动位置变化，浏览器外框至少为 1280×1000 像素，harness 标题完整可见，顶部蓝/绿色边界与中心 `VISION TARGET` 均可见。不得用最大化、DPI/缩放切换或窗口遮挡来代替目视确认。

第一个实际夹具必须是无点击的 `05-short-move-in-harness`。在点击 AutoFlow 的 Play 后，利用现有 3 秒倒计时回到 harness，确认指针先到 45% 端点，再到 55% 端点；操作员必须目视确认两个端点和 50% 中线都在绿色安全指针区域内，且操作员能够随时按物理 F12。`window_rect` 只提供窗口外框，不证明坐标属于 DOM 区域。任一端点靠近控件、日志、浏览器边框或安全区域外，立即停止并记为 BLOCKED，不得继续 `06`、`03`、`11`、`12` 或 `08`。

### 4. 通用记录、时延和停止条件

每个用例记录：开始 UTC、候选 SHA-256、Windows 版本、桌面/完整性级别、显示器/DPI、浏览器缩放、夹具 ID/name、动作、可见状态、停止请求时延、清理完成时延、AutoFlow 日志、harness 结果导出、截图和结论。

- **停止请求时延**：从物理 F12 按下到 UI 首次显示停止/清理状态，或观察到输入动作停止的时间。
- **清理完成时延**：从 F12 按下到 UI 明确进入安全终态，且 harness 不再显示夹具持有的键/按钮的时间。

本轮人工标准为停止请求时延不超过 500 ms；这不是硬实时 SLA。清理完成必须记录实测值，不得用等待更久掩盖不明确状态。只要状态不明确、仍显示 held、错误后未锁定或出现新输入，就失败。

下列任一情况立即停止全轮验收：

- F12 后仍产生新键盘/鼠标事件，或输入离开 harness；
- 键/鼠标按钮未释放、重复释放异常、held 状态无法解释；
- 清理失败后回到 `Idle`、允许再次播放或自动 rearm；
- 服务断开、桌面切换、锁屏/唤醒后自动继续；
- UI 与实际输入不一致，无法确认 PID、运行代际、ledger 或当前候选；
- 操作员失去物理控制，或故障测试需要猜测进程而非精确 PID/角色。

### 5. 分级放行

#### Level 0 — 静态完整性（无 GUI、无输入）

**前置条件：** 候选已构建但未运行；已完成第 2 节备份；候选 exe 和备份哈希已记录。

**步骤：**

1. 运行默认 Validate；逐一查看 JSON 和 `git diff --check` 输出。
2. 核对候选 SHA-256、基线提交、工作区来源和备份清单。
3. 确认仓库没有个人数据、密钥、意外绝对路径、`.rhai` 导入物或未授权测试宏。
4. 确认“渡鸦开门”未运行、未启用、未绑定；确认候选 PID 不存在。

**预期结果：** 所有夹具静态有效、默认禁用/无触发/once；没有启动应用、hook 或输入。

**证据：** Validate 完整输出、SHA-256、`git diff --check`、备份清单、`git status --short`、宏清单截图。

**失败/停止条件：** 任一 JSON 不是 `VALID`、哈希不符、出现 F10/F12 或用户绝对路径、发现“渡鸦开门”曾运行，立即停止，重新构建或恢复，不进入 Level 1。

**本级签字：** `Level 0 PASS / FAIL / BLOCKED；操作员____；复核人____；UTC____；证据____。`

#### Level 1 — 无输入生命周期、取消与显式恢复

**前置条件：** Level 0 通过；harness 已由操作员打开；只安装 `00` 和 `04`；记录浏览器窗口标题。

**步骤：**

1. 启动候选，确认初始状态安全，两个夹具仍禁用、空触发。
2. 从 UI 手动运行 `00-no-input-wait`，等待自然结束。
3. 手动运行 `04-cancel-rearm-no-input`，约 1 秒后按物理 F12；分别记录停止请求和清理完成。
4. F12 保持按下时尝试恢复，必须拒绝或保持不可用；松开后只在 UI 明确满足条件时显式恢复。
5. 再运行 `00`，确认新代际完成；重复停止不得影响下一次运行。

**预期结果：** harness 无键鼠事件；旧运行不污染新运行；未释放 F12 时不能 rearm；恢复不会自动播放。

**证据：** 状态/诊断日志、harness 导出（只应有人工事件）、两种时延记录、恢复前后截图。

**失败/停止条件：** 无输入夹具产生输入、自动恢复、held 不清、状态代际不一致或任何时延无法测量，立即停止，不进入 Level 2。

**本级签字：** `Level 1 PASS / FAIL / BLOCKED；stop-request____；cleanup____；操作员____；复核人____；证据____。`

#### Level 2 — 最小文本与单键

**前置条件：** Level 1 通过；输入法预测、快捷扩展和自动提交关闭；已完成 3.5 的固定几何准备和无点击短移动目视确认。

**步骤：**

1. 清空 harness 日志与输入框，准备把焦点放入输入框，但不要假设 Play 后焦点仍在此处。
2. 在 AutoFlow UI 点击 Play；利用 UI 的 3 秒倒计时立即返回 harness，明确点击并聚焦输入框，在倒计时结束前保持页面可见。
3. 若倒计时结束前未完成聚焦，立即取消/停止本次运行；不要在本级重试，先重新确认安全状态并重新从本级前置条件开始。
4. 确认恰好出现 `AUTOFLOW_MANUAL_SMOKE`，没有 Enter、快捷键或额外字符。

**预期结果：** 输入只进入 harness；key down/up 成对；结束时 held 为“无”。

**证据：** 输入框截图、harness 完整日志、AutoFlow 运行结果和候选哈希。

**失败/停止条件：** 任何额外字符、窗口外输入、遗漏 keyup 或 held 残留，立即停止；不要进入 Level 3。

#### Level 3 — 修饰键持有与物理 F12 释放

**前置条件：** Level 2 通过；Caps Lock/Num Lock 状态已记录；操作员可直接按到物理 F12；已完成固定几何门禁；仅准备 `02`。

**步骤：**

1. 在 AutoFlow UI 点击 Play；利用 3 秒倒计时返回 harness，明确点击安全指针区域使页面获得焦点，在倒计时结束前保持页面可见。
2. 若倒计时结束前未完成聚焦，立即取消/停止本次运行；不要在本级重试，先重新确认安全状态并重新从本级前置条件开始。
3. 观察 Shift held 后，在 30 秒人工等待标准内按下物理 F12；分别记录停止请求和清理完成，再松开 F12。
4. 确认 Shift 的 keyup 出现且 held 为“无”；手动输入普通字符，确认不再被 Shift 修饰。
5. 进入明确安全终态后显式恢复，再运行 Level 1 的 `00` 做 rearm。

**预期结果：** F12 先撤销播放权再清理；Shift 一定释放；失败时保持故障锁定而非自动回 Idle。

**证据：** F12 操作员记录、两种时延、harness keydown/keyup、状态截图、恢复日志。

**失败/停止条件：** F12 后仍有输入、Shift 未释放、按住 F12 可恢复、出现自动续播或状态不明，立即停止并按第 6 节恢复。

#### Level 4 — harness 内移动、单击与按钮持有释放

3. 确认没有窗口外点击；确认安全终态后显式恢复，再运行 `00`。

**预期结果：** 无窗口外点击、无残留按钮；所有坐标来自窗口矩形。按钮持有和拖拽属于 Level 7 隔离测试，本级不运行。

**失败/停止条件：** 轨迹离开区域、发生点击、取消后仍移动或状态不明，立即停止，不进入视觉等级。

#### Level 6 — 找图成功、miss 与 timeout

**前置条件：** Level 0–5 全部通过；DPI、浏览器缩放和窗口大小在本级保持不变；视觉资源准备步骤已完成但结果仍待人工确认。

**步骤：**

1. 按第 3.4 节从 harness 当前渲染截取目标，并通过 UI 导入；记录资源 ID、截图、DPI 和缩放。
2. 目标可见时运行 `10-image-success-template`，记录 UI/诊断中明确显示的 `MANUAL_TEST_IMAGE_HIT` 或 `MANUAL_TEST_IMAGE_NOT_FOUND_OR_TIMEOUT` 停止消息和耗时；本手册不声称 score、matched scale 或候选数，除非当前 UI 明确实际输出这些字段。
3. 用 harness 按钮隐藏目标；运行 `09-image-miss-timeout`，预期得到 `MANUAL_TEST_IMAGE_MISS_THEN_TIMEOUT`；如果得到 `MANUAL_TEST_IMAGE_INITIAL_LOOKUP_HIT` 或 `MANUAL_TEST_IMAGE_WAIT_LOOKUP_HIT`，记录为准备/视觉失败。不应有键鼠输入。
4. timeout 期间按 F12 做第二轮，确认轮询可取消；取消后没有后续动作。
5. 重新显示目标；移动窗口或切换 DPI 后不得沿用旧结果，记录重新查找。

**预期结果：** 成功/未找到、初始 miss/等待 timeout 通过 stop message outcome code 可区分；隐藏目标不伪造命中；timeout 与取消有界。黑盒视觉夹具没有下游输入，只能观察取消和没有晚返回结果，不能证明“视觉晚返回后不会到达下一次输入动作”；该属性仍依赖已有确定性自动化测试或专用证据，保留为未验证的人工黑盒边界。

**证据：** SVG 参考资源、当前机器截屏 PNG、UI 资源记录、实际 stop message outcome code、当前 UI 真正输出的视觉耗时字段、harness 导出、两种时延；不要补写运行时未输出的 score/scale/候选数。

**失败/停止条件：** 资源未通过 UI 导入、命中依赖固定旧截图、隐藏目标仍命中、outcome code 不符、timeout 无界、出现任何输入或窗口外动作，立即停止；黑盒没有下游输入时，不得把“未观察到输入”误记为已证明晚返回抑制。

#### Level 7 — 隔离的高风险、长序列、桌面/完整性和故障边界

**前置条件：** Level 0–6 全部通过；关闭其他应用；测试账户可随时注销；每个子用例只运行一个夹具，完成后完全退出并重新启动候选；建立本轮准确 GUI、安全服务、executor PID 与命令行记录。

**步骤：** 依次执行下列 7A–7E 子用例；每个子用例只在前一个子用例已完成记录、候选已重新启动且安全状态明确后开始。

##### 7A. 按钮保持与拖动（`03-held-left-f12`、`11-isolated-drag-f12`）

先从全新启动运行 `03-held-left-f12`，看到左键 held 后在 30 秒人工等待标准内按物理 F12；确认左键释放、没有继续移动或窗口外动作。完全退出并重新启动候选，再运行 `11-isolated-drag-f12`；确认窗口中心、45% 端点和 55% 端点都在安全指针区域，看到 drag/held 后按物理 F12，确认没有窗口外 drop。每个夹具独立记录停止请求和清理完成；任一失败立即停机，不继续 7B。

##### 7B. 独立可中断长序列（`12-isolated-long-sequence`）

这不是 `04` 的长等待重复：它由 12 个短往返移动组成，目的在于观察撤销后不会继续写入后续序列。只在空桌面、harness 可见、无其他夹具运行时启动；看到第二个或后续往返后按物理 F12。确认序列立即停止、指针不离开安全区域、没有点击/按键、没有后续动作。记录已完成的序号、停止请求、清理完成和重新启动后的 ledger。静态步骤配对不能证明此取消清理，必须以日志和人工观察为准。

##### 7C. 锁屏、睡眠/唤醒与桌面切换

先只运行无输入 `04`。由操作员人工锁屏、解锁；候选必须处于停止或 `FaultLocked`，不得自动续播。完全退出并重新启动候选后，再用 `04` 做一次睡眠/唤醒；解锁后预期相同。若测试环境有受控安全桌面切换，记录切换前后桌面、焦点和可见性；候选不得在桌面切换期间继续发送输入。未达到明确安全终态前不得运行输入夹具。

##### 7D. 完整性级别转换

在标准用户桌面启动候选并记录 GUI、安全服务和 executor 的 PID/完整性级别。只使用已批准的、无业务副作用的本地 Windows 管理操作，由操作员人工触发一次受控 UAC/高完整性桌面切换，再返回普通桌面；不要把 AutoFlow 候选提升运行。观察候选是否停止、撤销权限并保持安全，返回后不得自动 rearm。无法提供受控 UAC 观测、无法记录完整性级别或需要猜测目标窗口时记 `BLOCKED`，不以“未观察到问题”代替通过。

##### 7E. GUI、安全服务、executor 精确 PID/角色故障

每一轮从全新启动开始，任务管理器开启命令行列，先确认唯一的 GUI、安全服务、executor PID 和角色；不能精确识别就跳过并记阻塞，禁止按名称猜测或结束全部相关进程。分别对 executor、安全服务、GUI 做终止一轮，再分别对 executor、安全服务做挂起一轮并按物理 F12。记录管道断开、租约丢失、停止请求、清理完成和最终故障锁定。进程死亡、挂起、管道断开或超时后不得继续/重放旧动作，也不得自动恢复输入权限。只有无输入故障矩阵通过后，才可在 `02` 或 `03` 的 held 状态做一次对应故障；释放不明确立即执行精确角色恢复或注销。

**预期结果：** 每个高风险子用例完全隔离；拖动、长序列、锁屏/睡眠、桌面/完整性切换、GUI/安全服务/executor 故障都先撤销输入权限；清理失败保持 `FaultLocked`；没有旧代际输入、自动续播或模糊进程操作。

**证据：** 每个子用例独立的候选哈希、PID/命令行/角色/完整性截图、桌面切换记录、任务管理器截图、AutoFlow 诊断、Windows 事件记录、harness 导出和两种时延。native `SendInput` 部分成功/释放失败仍标注“专用 fault-injection build 未验证”。

**失败/停止条件：** 任一子用例发生窗口外输入、按钮/键未释放、桌面返回后续播、完整性级别无法确认、进程目标不唯一、故障后非锁定恢复，立即停止整轮并按第 6 节精确恢复。

**本级签字：** `Level 7 PASS / FAIL / BLOCKED；7A____；7B____；7C____；7D____；7E____；stop-request____；cleanup____；操作员____；复核人____；证据____。`

### 6. 应急停止与精确恢复

1. 立即按一次物理 F12 并松开；记录停止请求和清理完成，不要反复启动夹具。
2. 若鼠标仍按住或修饰键仍生效，不要点击业务窗口；使用第二设备或安全系统界面记录现象。
3. 打开任务管理器，核对本轮候选的精确 PID、完整命令行和角色；只结束该 PID 的 GUI、安全服务或 executor。禁止“结束所有进程”、模糊名称、父子树全杀或未经确认的系统进程。
4. 若状态仍不可信，注销测试账户；注销不可达时重启测试机。该轮记失败，不把重启当成通过证据。
5. 保存日志、截图、harness 导出和时间点；不要在同一会话继续测试。重新开始前完成备份恢复/ledger 分析，并从 Level 0 重新执行。
