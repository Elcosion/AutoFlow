# Runtime safety refactor — checkpoint

Status: implementation in progress; **not cleared for real-input testing**.

## Release-failure fault-latch checkpoint

The central cleanup-report handler now fault-locks the lifecycle controller on
any unsuccessful release report. A subsequent empty/successful cleanup report
may update remaining-input bookkeeping but cannot authorize automatic playback
or background injection. Recovery remains an explicit, separately validated
operation. The input-free regression
`failed_release_report_latches_fault_even_after_a_later_empty_cleanup` covers
that distinction. Verification: 290 library tests and 17 mock-input subprocess
tests pass; all-target/all-feature Clippy with warnings denied, Rust format check
and `git diff --check` pass. No real desktop input was injected.

Important distinction for the priority-cleanup checkpoint below: completion of
the cleanup callback is not proof that native releases succeeded. Lane failure
or panic does not publish completion; a returned callback still requires the
ledger/report, fault-state and actual thread-exit checks before safe shutdown.

## F12 behavior-recording retention checkpoint — 2026-09-18

The confirmed destructive `BehaviorRecorder::reset` in emergency cleanup has
been replaced by an inactive, retained capture state. A first freeze records a
stable stop timestamp; repeated freeze/config refresh preserves the sole bounded
raw-event buffer, counters, name and retention policy. New behavior recordings
reject an unclaimed stopped session before initialization can overwrite it.
Complete results are claimed once through the existing stop endpoint, which no
longer drains an already successfully drained queue a second time. Both status
and result duration use `stopped_at - started_at`, not continued wall time or a
stopped-at start anchor. The 250,000-event limit remains unchanged.

Emergency cleanup attempts to close/drain pending admission even when the queue
has already reported loss. Failed normal/emergency drain freezes an incomplete
session without generating a profile; the incomplete flag is sticky and does
not authorize a new recording. Failed drain or unavailable recorder bookkeeping
still prevents confirmed cleanup. An unavailable recorder mutex is NOT treated
as an empty/complete capture: its data is retained and cleanup stays unconfirmed;
this does not prove a bounded final recorder-state transition under every lock
contention/native-call fault. No safety admission gate was removed or weakened.

Five new regression tests cover frozen duration/one-time claim, sticky incomplete
capture, actual mock HookShared emergency retention across repeated stop/config
refresh, emergency admission loss and ordinary stop admission loss. Hook tests
use synthetic events, mocked detector health and empty input ledgers, not native
hook installation, user macros or desktop input injection. Existing cap coverage
also continues to pass.

## Implemented in this checkpoint

- Single lifecycle authority with run identity and cancellation generation.
- Admission leases prevent rejected/cancelled starts from damaging active runs.
- Starting and Cleaning deny new playback/background injection.
- Input permits reject cancelled/stale runs at the injection boundary; tracked releases remain permitted.
- Each playback retains its own input ledger; failed cleanup retains that ledger for recovery.
- Physical emergency-key polling no longer uses RegisterHotKey(F12), and does not wait for configuration locks.
- Shutdown ledger snapshots are nonblocking and fail closed on contention/poisoning.
- Script stop messages are returned as outcomes rather than displayed inside the interpreter. All playback/start error dialogs now publish into a nonblocking, bounded UI mailbox. The main UI shows escaped text and explicitly acknowledges notices; a remount/late IPC response cannot consume them. Confirmation does not start/resume execution. The former MessageBox/AttachThreadInput path is removed.
- Cleanup operation-lock acquisition has a 100ms deadline; failure retains the ledger and reports unsafe. This does not impose a deadline on an already-entered Windows system call.
- Versioned, size-limited executor protocol validates private-session credentials, run identity/generation, exact sequence, coordinates, text length, and bounded pointer plans. Revocation permanently rejects subsequent actions for that receiver. The production interpreter now uses the private transport.
- Input-free protocol probe exercises real child-process pipes. It deliberately has no injection authority and is not the production executor.
- `SupervisedWorker` owns a Windows Job Object with kill-on-close, completes job assignment before exposing the bootstrap pipe, hides the worker console, revokes via the supplied callback before disconnect/termination, and confirms worker exit with bounded polling. Dropping a worker performs last-resort containment, not input cleanup. Production playback uses this supervision.
- Playback input-ledger registration failures now reject startup and fault-lock the controller instead of silently ignoring a poisoned registry.
- Emergency readiness now requires a recent monotonic heartbeat, not just a thread ID. A per-run watchdog revokes the permit if heartbeat readiness fails. Startup also waits for an actual heartbeat. Desktop availability detection remains pending.
- Production graph/Rhai interpretation now starts the same executable in `--runtime-executor` mode before Tauri initialization. This path installs no hooks and uses only a private-pipe AutomationInput proxy; parent requests still pass through the run-scoped Windows input permit and ledger. Graph combination/progress semantics and retained-button state across repeat iterations are preserved. Vision processing is created in the executor; biomimetic sampling still lives in the parent for now.
- Bootstrap and replies use one-entry channels; a blocked pipe write has a 500ms deadline and cannot block the cancellation loop. End messages are authenticated and sequenced as well as input requests. Parent teardown revokes on failure, terminates the job, and bounds communication-thread shutdown checks. Execution is not automatically replayed after disconnect.
- Session credentials are generated with Windows BCryptGenRandom and passed only through private pipes, never command-line arguments.
- Permissionless recovery key/button releases now check ledger membership inside the serialized operation, preventing blind release of untracked physical input.
- Production UI now uses a `RuntimeBackend` private-pipe proxy rather than constructing hooks. A separate `--runtime-safety` process owns hooks, controller and ledgers; the executor remains separately job-supervised. Recording focus boundaries use the UI PID, not the safety-service PID.
- Independent named heartbeat/stop events bypass the ordinary RPC queue. Parent process death, lease loss and broken control pipes revoke permission. One-entry RPC queues and 64KiB document chunks limit buffering; documents have a 64MiB ceiling. Startup errors revoke the lease. Valid admission errors do not disconnect an active service.
- A session-local named ownership mutex prevents a second production input authority. Mock integration fixtures use distinct namespaces and never install hooks or inject OS input. Production authority collision/exit behavior still needs complete acceptance testing.
- Safety-service reply writes now run on a one-entry document-writer queue; the authority waits at most 500ms and cannot reuse a timed-out writer. JSON serialization stops at the document ceiling rather than allocating an oversized serialized buffer first.
- The emergency thread queries its desktop's `UOI_IO` read-only state. A ready-to-unavailable transition latches a controller fault and revokes input. Successful cleanup and repeated stop do not clear the latch; service recovery explicitly checks detector readiness, desktop availability, no active run/cleanup worker, empty ledgers and no recovery-required flag. The main UI now offers explicit recovery only for a locked state, disables recovery for unknown cleanup/service disconnect and never calls playback as part of recovery. The full failure-recovery matrix remains pending.
- Transient RPC queue contention is returned as a query error, not fabricated FaultLocked/inactive-recording status. Recording and behavior status failures propagate rather than declaring a recording ended. The UI observer ignores busy responses and has no overlapping polls.
- Background convenience tasks capture a separate admission generation. Macro admission and stop invalidate it; remap/text-expansion permission checks reject old work even after normal macro completion.
- Text expansion now uses one worker with eight pending-task slots instead of spawning one thread per match. Submission is nonblocking; full/closed queues keep the physical input and publish a bounded, coalesced notice. Replacement payloads above 16KiB are rejected before copying/enqueueing. Shutdown closes admission and discards pending work. A channel-controlled mock test proves queue capacity and worker exit without consuming discarded tasks. Remap sends, recording locks and other hook-side work remain to be migrated.
- Emergency registry snapshots are now fallible/nonblocking, never an empty-list fallback on contention or poisoning. Unknown registry/bookkeeping latches a fault and cannot report safe cleanup. Ledger release precedes recording-result and convenience bookkeeping; those emergency follow-up locks use try_lock, retaining unavailable recording data instead of clearing it. Input-state membership/diagnostic reads are nonblocking. Cleanup retains successfully acquired ledger guards through release and ledger removal, avoiding post-release lock reacquisition. Unavailable ledger locks retain tracked inputs and report unsafe. Input diagnostic updates use try_lock and cannot delay release. Diagnostics disk writing and ordinary hook-side paths still need the remaining boundedness audit.
- Production permission-aware key/button transactions now acquire ledger guards before the OS side effect and retain them through registration/removal. There is no post-send reacquisition failure that can lose a successful press. Recovery releases also refuse unavailable ledgers before sending. A mock in-flight cancellation regression confirms successful presses remain tracked for cleanup. Already-admitted system calls may finish after revocation; this boundary is documented rather than claiming they can be forcibly undone.
- Safety diagnostics now use one writer per diagnostics instance and a 64-entry nonblocking queue, rather than synchronous producer disk I/O or one thread per event. Records bound field counts/string lengths, preserve reserved sequence/timestamp metadata and report cumulative lost events (queue overflow and write failures). File retention removes complete JSONL records rather than cutting JSON mid-line. A blocked sink cannot delay input release, but queued records can still be lost on abrupt process termination; durable terminal flush and full-run retention remain acceptance work.
- Macro and text-expansion Unicode input now use the shared key ledger with a private UTF-16 input namespace. Later units require a fresh permission check. Diagnostic descriptions/failure values redact the Unicode unit content. Regression fixtures cover failed release/recovery, in-flight cancellation and supplementary-character surrogate pairs without actual system input.
- All input transaction operation-lock acquisition, including ordinary injection and recovery releases, now uses try_lock with a 100ms contention deadline and cancellation checks while waiting. No sender uses unbounded operation.lock. Test setup down helpers now call the same permission-aware ledger transactions as production instead of separate post-send-lock implementations. Mock tests hold the lock until callers have returned, proving failed down/release/movement do not inject or discard registered input. Already-entered OS calls remain outside this acquisition bound; hook-side remap execution still needs worker migration.
- Low-level macro triggers, native macro hotkeys and the native clicker now share one bounded startup worker instead of spawning a thread per trigger. A pending-start atomic limits admission to one task across queue and handler; stopped generations are rejected both at submission and dispatch. Hold dispatch checks physical trigger release before startup. Shutdown closes the startup queue. Mock tests prove absent worker rejection, 100 duplicate admissions rejected while the handler is blocked and old-generation rejection, without real hooks/input. Full UI-versus-trigger admission reservation races and remaining callback locks/remap/recording work still require acceptance review.
- Controller startup checks an admission revision inside the lifecycle mutex, in addition to emergency generation. Queued trigger tasks capture the revision before cloning their payload. Private safety-service protocol version 2 carries the cached revision on UI requests and current revision on replies, so a stale cross-process request is not refreshed at dispatch. Another admission invalidates the old revision even if it finishes normally or aborts during validation. Deterministic controller regressions prove those two formerly replayable scenarios are rejected. Earlier hook event capture and the complete transport interleaving matrix still require acceptance review.
- Playback, macro-recording and behavior-recording startup now share a nonblocking mode-admission mutex. Recording activation and playback admission cannot pass simultaneous independent idle checks. Playback refuses an active macro recording; starting another recording refuses uncollected completed steps instead of overwriting them. Macro recording refuses active behavior training; behavior startup checks the controller's lifecycle instead of only the display running flag. Admission-state queries use try_lock where recording data is inspected. Mock regressions prove recorded steps/pending results survive rejection and the atomic stop signal remains independent of mode admission. Remaining capture callbacks and mode/trigger transport interleavings still require acceptance review.
- Executor/communication exit uncertainty now has a separate latched containment flag, not the resettable input-cleanup flag. The executor supervisor reports typed stop causes; production no longer infers containment failure from Chinese error substrings. Successful empty-ledger cleanup cannot clear this flag. Recovery, startup, safe finalization/shutdown and emergency safe-status checks require containment confirmation independently. An input-free regression proves cleanup can clear its own flag while recovery remains FaultLocked on unconfirmed containment. Current containment uncertainty requires application/process shutdown verification rather than pretending a new cleanup proves worker exit; retained process-handle revalidation remains future acceptance work.
- The UI safety client retains a duplicated owned process handle for the exact child, independently of its RPC actor. Exit observation distinguishes Alive/Exited/Unknown; bounded confirmation cannot report success on timeout/query failure. Production shutdown separately requires a positive cleanup response and retained-handle-confirmed process exit, revoking the lease even when shutdown RPC fails. No PID-only polling or forced safety-service kill is used. A new input-free subprocess test checks live-state rejection, active mock shutdown, actual exit confirmation and closed-client rejection. Blocked service-command cleanup/exit containment remains required.
- Playback-thread execution-frame ownership is tracked separately from controller active-run state via a scope lease tagged with the instance ID. Startup, recovery and shutdown safety confirmation refuse an outstanding lease even if controller finalization already returned to idle. Stale lease destruction cannot clear another instance's ownership; panic unwinding fault-locks and requests emergency cleanup. Trigger-state release now uses try_lock and requires physical rearming after contention instead of waiting indefinitely. Mock tests prove idle controller does not bypass outstanding ownership and stale lease teardown does not clear current ownership. This is execution-frame ownership, not proof of an OS thread handle's final signaled state; complete exit/fault acceptance remains pending.
- Remap down/up now execute on one bounded worker (32 pending tasks), not inside the low-level keyboard hook. Nonblocking down submission reserves source/target before queueing so immediate up remains associated; failed admission rolls back reservation and preserves physical input. Duplicate target reservations are rejected. Up submission is recovery-only; a full/unavailable queue requests the independent emergency stop. Invalidated down permission introduces no OS input and does not cancel a newer macro. Shutdown closes remap admission. A channel-controlled mock regression verifies order, reservation rollback and priority stop on full release queue. Cross-producer ledger ownership, canceled reservation lifetime and recording/remap admission remain acceptance work; no complete safety claim is made.
- Unit-test construction does not install Windows hooks. Test diagnostics use a temporary directory, not production AppData diagnostics.
